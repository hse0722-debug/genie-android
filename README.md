# 지니 다운 도우미 9.0.0 — 새로고침 업데이트

PC와 Android용 고정 실행기입니다. 처음 한 번 설치하면 작업 코드는 GitHub에서 읽습니다. 운영자가 새 작업 버전을 배포한 뒤 **중단 → 지니 페이지 새로고침 → 시작**하면 반영됩니다. 진행 중인 작업은 시작 당시 버전을 유지합니다. 패널 제목에 실제 작업 코드 버전이 표시됩니다.

## 기존 사용자도 이번에는 한 번 교체

8.5.2까지의 설치본에는 자동 로딩 기능이 없으므로 이번 9.0.0 실행기로 한 번 교체해야 합니다. 계정 파일을 보관하고 작업을 중단한 뒤 설치하세요. 이전 도우미와 새 도우미를 동시에 켜두지 마세요.

### PC Chrome

1. [설치 ZIP](https://raw.githubusercontent.com/hse0722-debug/genie-android/main/genie_down_helper_github.zip)을 받아 압축을 풉니다.
2. `chrome://extensions`에서 개발자 모드를 켭니다.
3. 기존 설치 폴더에 새 파일을 덮어썼다면 확장 프로그램의 새로고침 버튼을 누릅니다. 새로 설치한다면 **압축해제된 확장 프로그램을 로드합니다**에서 manifest.json이 있는 폴더를 선택합니다.
4. 확장 프로그램 **세부정보 → 사용자 스크립트 허용(Allow User Scripts)**을 켭니다. Chrome 138 미만은 개발자 모드를 사용합니다.
5. 기존 지니 탭과 결제 팝업을 닫고 지니를 다시 엽니다. 초기 설정 후 새로고침 안내가 나타나면 한 번 새로고침합니다.
6. 패널에 9.0.0이 표시되는지 확인하고 계정 파일을 불러옵니다.

### Android 폰·태블릿

Android Chrome에서는 이 확장 프로그램을 설치할 수 없습니다. 기존에 사용한 **확장 프로그램 설치가 가능한 Edge Canary** 방식입니다. 이번 실행기는 추가로 `userScripts`와 사용자 스크립트 메시징 API 지원이 필요합니다. **Android 실기기에서는 아직 검증하지 않았으며**, 브라우저에 필요한 API/허용 메뉴가 없으면 작동하지 않습니다. 이 경우 기존 8.5.2를 유지하고 브라우저 지원 여부를 확인해야 합니다.

1. [Android 설치 파일](https://raw.githubusercontent.com/hse0722-debug/genie-android/main/genie-android.bin)을 받습니다.
2. 파일 관리자에서 `genie-android.crx`로 이름을 바꿉니다. BIN과 CRX는 같은 서명된 파일입니다.
3. Edge Canary의 개발자 옵션 **Extension install by crx**에서 설치/갱신합니다. 기존과 같은 서명 키를 사용했습니다.
4. 확장 프로그램 세부정보에서 **사용자 스크립트 허용**을 켭니다. 브라우저 버전에 따라 개발자 모드로 허용할 수 있습니다.
5. 지니를 **데스크톱 사이트**로 열고 새로고침합니다. 로더 오류가 나오면 지원 API와 설정을 확인합니다.

## 유지한 기능

- 로그인 → 앨범/곡 좋아요 → 개별 곡 결제 → 지니캐시 선택 → 약관/구매 동의 → 최종 결제 → 다운로드 시작 감지 → 다음 계정.
- 기존 결제 화면 선택자와 단계별 대기시간을 유지했습니다. 최종 결제 전 0.9초, 다운로드 감지 후 다음 곡 2초/다음 계정 4초입니다.
- 다운로드는 브라우저 downloads API로 감지합니다. 파일 전체 저장 완료가 아닌 다운로드 시작을 의미합니다.
- 여러 탭·프레임의 중복 클릭 방지, 중단 후 지연 클릭 차단을 유지합니다.
- 다운로드 이벤트를 저장하고 페이지 연결이 바뀌면 재전달합니다. 이미 처리한 다운로드로 계정이 두 번 넘어가지 않도록 확인합니다.
- 도우미 인증 비밀번호는 없으며 지니 로그인 비밀번호는 그대로 필요합니다.
- 아이폰과 같은 게시 CSV에서 C3:C4, D3:D4를 읽어 이름: 시드로 표시합니다. 정상 조회 안내 문구는 숨겨져 있습니다.
- 계정·비밀번호·진행 상태는 각자의 브라우저에 저장합니다. GitHub에는 코드/버전만 요청합니다. 여러 사용자의 계정을 배정하는 서버는 없습니다.

## 운영자가 업데이트하는 방법

작업 코드는 `content.js`(화면/작업)와 `engine.js`(결제 실행 제어, 다운로드 후 처리, 시트 해석)입니다. 수정 후 Node.js에서 아래를 실행합니다.

```
node build-release.cjs 9.0.1
```

생성된 `genie-content-9.0.1.js`, `genie-engine-9.0.1.js`, `release.json`을 같은 커밋으로 저장소 최상위에 올립니다. 편집한 원본 content.js/engine.js도 함께 올리면 다음 수정에 사용할 수 있습니다. **기존 버전 파일을 덮어쓰지 말고 매번 버전 번호를 올리세요.** release.json이 현재 배포 버전을 가리키며 실행기는 SHA-256을 확인합니다.

일반 작업 수정 시 설치 ZIP/CRX/BIN을 다시 만들 필요가 없습니다. 기존 사용자는 작업 중단 후 지니 페이지를 새로고침하면 됩니다. GitHub 반영에 잠시 시간이 걸릴 수 있으므로 패널의 버전을 확인하세요.

실행기 자체(`background.js`, `launcher.js`, `user-runtime.js`)나 manifest 권한/API를 바꾸는 경우에는 설치 파일 교체가 필요할 수 있습니다. 모든 종류의 변경에 영구적으로 재설치가 필요 없다는 의미는 아닙니다. 이 패키지는 GitHub에서 직접 배포하는 버전입니다.

## 검증

모의 환경에서 CSV 조회·표시·오류, 동시 실행 요청 30개, 두 문서의 중복 다운로드 클릭, 결제 단계별 1회 클릭, 중단 직후 클릭 차단, 다운로드 중복/페이지 재연결 재처리, 새 버전 조회/진행 버전 고정/변조된 파일 거부, 원격 엔진과 네이티브 실행기 간 메시지 연결을 검증했습니다. CRX3 서명과 ZIP 내용도 확인했습니다.

실제 음원 구매나 Android 실기기 결제·다운로드는 실행하지 않았습니다. 설치 후 먼저 한 계정으로 동작을 확인해주세요.
